# 视觉目标卡 —— 接口故障根因定位（桌面常驻程序）

> 本文件是**结构化视觉目标**，不是界面效果图。
> 本环境不具备图像生成能力，因此 `docs/concepts/` 下**不放任何图片**；真实运行画面在 `docs/screenshots/` 采集，两者不可互相冒充。
> README 的「概念 / 实测对照」一节引用本文件并诚实标注两侧差距。

## 1. 交付形态（约束视觉目标的前提）

- 形态：**桌面常驻程序**（主窗口 + 系统托盘），Rust + egui/eframe 主窗，tray-icon 托盘。
- 场景：**信息科值班机**，夜班工程师轮值使用；值班人**不开终端**。
- 因此视觉目标必须是「一个窗口 + 一个托盘图标」能讲清的画面，**不是**终端表格、不是浏览器控制台、不是营销落地页。

## 2. 三个状态

### 状态 A —— 起始态（刚启动，还没有任何结论）

- 画面：主窗口空窗，顶部是标题条与一句话说明；主体是一块空态占位块（图标 + 一句说明 + 一个「立即采集一次」主按钮）。
- 右上角三枚「来源连通状态」小徽标并排：`ESB 流水` / `指标` / `错误日志`，未连通时为灰底灰字，连通后为指标绿底色。
- 托盘图标为**灰色**（未采集 / 无待确认）。
- 信息层级：页面标题 > 区块标题 > 空态说明 > 辅助文字，共四层。

### 状态 B —— 首个可用瞬间（第一次跑出结论）

- 画面：窗口分左右两栏。左侧是候选列表（每行一个接口编码 + 劣化倍数 + 一条来源色条）；右侧是选中项的**证据区**（三段可折叠：接口流水 / 错误日志 / 主机指标），每段下方列出带证据行 ID 的原文行。
- 选中行高亮用**琥珀色**左边框表示「待人工确认」，不用红色。
- 底部状态条一行：`窗口 20:00–08:00 ｜ 来源 3/3 ｜ 候选 3 ｜ 模型：规则基线（降级）｜ 状态：候选已排序`。
- 托盘图标仍为**灰色**（还没有待确认项）。

### 状态 C —— 成形态（候选排序 + 归因卡 + 待确认）

- 画面：左侧候选列表带序号与劣化倍数条（条长按倍数线性映射，倍数越大条越长）；右侧上部是**归因卡**（一句结论 + 置信度 + 证据引用链接 + 一句「下一步该看什么」），下部是证据区。
- 归因卡下方是「确认建单」主按钮（每屏只有一个主色按钮），点击后弹出确认模态，逐条列出将要提交的字段。
- 顶部若模型不可达，挂一条**琥珀色**横幅：「模型不可达，以下为规则基线结论」。
- 托盘图标变**琥珀色**（有待确认项）；建单成功后转**绿色**。

## 3. 配色语义（只用四个语义色，不用红绿对立）

| 语义 | 色值 | 用在哪 |
|------|------|--------|
| 主背景 | `#14181F` | 窗口底色、深色运维工作台基调 |
| 流水蓝 | `#4C8DFF` | 来源 = `esb_audit`（接口流水）的色条与徽标 |
| 日志橙 | `#E8A33D` | 来源 = `app_log`（错误日志）的色条与徽标 |
| 指标绿 | `#3FB984` | 来源 = `prom`（主机指标）的色条与徽标；「已连通 / 已建单」正向状态 |
| 待确认琥珀 | `#F0B429` | 「待人工确认」左边框、降级横幅、托盘待确认态 |

- 中性灰阶：`#0E1116`（更深一层的卡片底）/ `#1C212A`（分隔线）/ `#8A93A3`（辅助文字）/ `#E6EAF2`（正文）。
- 危险与破坏性操作（作废结论、清理本地数据）使用**琥珀 + 二次确认模态**，不用大红块压屏；只有删除本地数据这类不可逆动作才允许红色描边按钮。
- 四个语义色在 `#14181F` 背景上的对比度均需 ≥ 3:1（由 `tests/ui_theme.rs` 单测锁定）。

## 4. 字体层级与栅格

- 字体族：中文系统栈 `-apple-system, "PingFang SC", "Microsoft YaHei"`；接口编码、延迟数值、证据行 ID、倍数用**等宽字体**（便于竖排比对与跨行核对）。
- 层级四档：页面标题 20px / 区块标题 15px / 正文 13px / 辅助文字 12px；数字统一 `tabular-nums` 等宽对齐。
- 间距走 **8px 栅格**（4 / 8 / 12 / 16 / 24 / 32），圆角分卡片 8px / 浮层 12px / 模态 16px 三级。
- 布局：左侧候选列表固定宽度（约 320px）+ 右侧详情区自适应；证据区三段可折叠，默认展开第一段。
- 响应式两档：1280（左右并排）与 768（单栏堆叠，候选列表折叠为顶部下拉），关键表格不横向溢出。

## 5. 组件状态（必须可见的四态 + 三态）

- 按钮：hover / active / disabled / loading 四态；「确认建单」在提交中显示 loading 且禁用重复点击。
- 输入框：focus 可见环；错误态红框 + 具体提示文案（写清是哪个配置项缺失）。
- 列表 / 表格：sticky 表头、行 hover 变色、超长文本截断并可悬停看全文。
- **加载态**：骨架条（不转圈）；**空态**：图标 + 说明 + 行动入口（见状态 A）；**错误态**：说明 + 「重试」按钮。三态在主工作台都要有。

## 6. 必须可达的约束（只画当前依赖真能做出来的东西）

- 界面元素限于：文本、矩形/圆角矩形容器、列表与表格、折叠区、徽标、进度条（倍数条 / 骨架条）、模态框、内联 SVG 图标（托盘状态三色与来源图标）、toast 提示。
- **不出现**：三维场景、地图、WebGL 图表、实时动效大盘、动画库特效；不引入图表库，数值一律用文本 + 条形表达。
- 托盘只表达三态（灰 / 绿 / 琥珀），不做托盘内嵌面板。
- 所有配色、间距、字号必须来自集中定义的 token，界面代码里**不写死色值**。

## 7. 与实测证据的对照口径

- 视觉目标描述的是**信息层级与用色意图**；实测截图反映的是**当前实现的实际排版、密度与状态覆盖**。
- 两者必然有差距（例如目标里的骨架条在实测里可能只是文字提示、响应式只落了一档）。README「概念 / 实测对照」一节须写清差在哪，**不得**声称两者完全一致，**不得**生成事后效果图抹平差距。
