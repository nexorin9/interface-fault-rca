# 接口故障根因定位

> 夜班值班工程师把院内接口流水、主机指标和错误日志三处指向值班机上的这个程序，窗口里直接看到「昨夜是哪条接口先开始变慢」，每条结论都带可点开的原文证据；点确认之后，它才把带证据的说明写进运维工单系统。

这是一个装在信息科值班机上的桌面常驻程序（主窗口 + 系统托盘），不是网页，也不是命令行工具。值班人不开终端：程序每天定时把三路来源收进一张统一的运行事件表，故障告警触发时把窗口内劣化最明显的接口排在最前面，每条结论都指着具体的流水行、日志行和指标采样点。

程序对院内系统**只读**。唯一会写出去的动作，是值班人点「确认建单」之后向运维工单系统提交一条工单。它不自动建单、不自动改任何配置、不自动重启服务，也不替人判断业务该怎么做。采集与归因全程只涉及接口、服务、主机维度，**不落患者可识别明细**。

## 适用场景 / 目标岗位

| 岗位 | 什么时候用 | 得到什么 |
|------|------------|----------|
| 信息科运维值班工程师 | 夜班接口告警亮了，早 08:00 交班前 | 按劣化倍数排好的「昨夜先坏的接口」清单，每条带流水、日志、指标的原文证据 |
| 值班主管 | 早交班要口头讲清楚昨夜到底出了什么事 | 一段能直接贴进交班记录的说明文字，附证据引用；确认后已有工单号 |
| 接口登记维护人（信息科） | 每周维护接口登记表时 | 哪些接口码没登记、哪些一个码对多个服务的缺口清单，可直接分派补录 |
| 夜班替班工程师 | 交接班想快速回溯上次同类问题当时怎么判的 | 同一时间窗的历史结论与当时的判断依据，逐条可复核 |

## 能力要点

- **一夜之间谁先坏的，有答案了**：接口流水、主机指标、错误日志被收进同一张事件表，用「当前窗口相对基线的劣化倍数」排序，不再需要人工把三处时间戳凑到一张纸上对。
- **每条结论都能点回原文**：证据行 ID（如 `flow#a1923`）可回查定位到具体那一行，重启程序后依然对得上；写进工单里的引用，重新打开仍然能翻到当时的流水与日志。
- **接口自己变慢、还是下游被拖慢、还是厂商返回变了，分得开**：跨源判断由模型给出，但只认本次窗口里真实存在的证据行；引用不存在的行、引用窗口外的行、引用没登记的接口，整条候选直接丢弃而不是猜。
- **模型不可达时照样有结论**：规则基线独立算出排序结果，界面顶部明确挂出「模型不可达，以下为规则基线结论」，不会拿旧结论或空结论充数，人工照样可以确认建单。
- **结论停在待确认**：程序只把状态推到「候选已排序」，再往下的「待确认」「已建单」两个状态一个只能由人点、一个只能由建单真实成功触发，任何自动流程都推不动。
- **值班机不失控**：查询有扫描行数与内存上限，超出即降级为「Top-N 候选 + 窗口过大提示」，而不是把机器拖死；本地数据按保留期滚动清理。

## 快速开始

### 依赖

- Rust 1.75 及以上（`cargo` 构建，产出单个可执行文件）
- 桌面环境：Windows 10/11 或 macOS，用于主窗口与系统托盘
- 院内三处**只读**来源：ESB 接口流水库（只读账号）、指标端点、错误日志目录
- 运维工单系统地址与令牌（仅在需要建单时使用）

### 安装

```bash
# 拉取源码并构建发布版（单 exe，不装中心服务、不装数据库）
git clone <本仓库地址>
cd interface-fault-rca
cargo build --release

# 产物：target/release/interface-fault-rca
```

### 配置

凭据一律走环境变量。把 `.env.example` 里的每一项按实际值写进值班机的环境变量（或开机自启脚本里注入），程序不读仓库里的任何密钥文件。

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `ESB_AUDIT_DB_HOST` / `_PORT` / `_USER` / `_PASSWORD` / `_NAME` | 无（必填） | 院内 ESB 接口流水库只读账号；缺任一项启动即失败 |
| `PROM_BASE_URL` / `PROM_BEARER_TOKEN` | 无（必填） | 主机与中间件指标端点及访问令牌 |
| `ESB_LOG_DIR` / `APP_LOG_DIR` | 无（必填） | 网关与应用错误日志目录绝对路径（只读） |
| `OPS_TICKET_BASE_URL` / `OPS_TICKET_TOKEN` | 无（建单时必填） | 运维工单系统地址与访问令牌 |
| `MODEL_BASE_URL` / `MODEL_API_KEY` / `MODEL_NAME` | 无（可缺） | 归因模型端点；缺任一项自动走规则基线并标注降级 |
| `MODEL_TIMEOUT_SEC` / `MODEL_MAX_RETRIES` | `30` / `2` | 模型调用超时（秒）与重试次数 |
| 保留期天数 / 扫描行数上限 / 查询内存上限 | `7` 天 / 见 `config/` | 本地数据保留天数、单次查询允许扫描的最大行数与内存预算 |

列名映射、来源路由、基线阈值与排序权重全部放在 `config/pipelines.toml` 与 `config/interface-dict.toml`，改配置即改行为，不需要改代码。

> 只想把程序跑起来看结果：**看 [`docs/RUNBOOK.md`](docs/RUNBOOK.md)**（唯一入口说明：命令、参数、默认值、输入样例、产物路径、字段怎么核对，末尾贴一次真实运行回显）。

## 命令 / API / 配置说明

### 关键配置项

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `ESB_AUDIT_DB_*` | 无 | ESB 流水库连接位；**只读账号**，程序不执行任何写语句 |
| `PROM_BASE_URL` / `PROM_BEARER_TOKEN` | 无 | 指标端点；请求头 `Authorization: Bearer` |
| `ESB_LOG_DIR` / `APP_LOG_DIR` | 无 | 错误日志目录；程序只读，文件内容不外传 |
| `OPS_TICKET_BASE_URL` / `OPS_TICKET_TOKEN` | 无 | 工单系统；请求头带 `Idempotency-Key`，同窗口不重复建单 |
| `MODEL_*` | 见上表 | 模型端点；业务层只经一个模型网关调用，不绑定具体厂商 |
| `config/pipelines.toml` | 随仓库 | 三条来源各一条具名带版本的摄取管线 + 列名映射表 |
| `config/interface-dict.toml` | 随仓库 | 接口登记口径的实体绑定字典（别名 ↔ 规范码 ↔ 服务 ↔ 主机） |

### CLI 子命令 / 接口端点

| 命令或路径 | 用途 | 关键参数 |
|------------|------|----------|
| `interface-fault-rca` | 启动桌面常驻程序（主窗口 + 系统托盘） | `--config-dir`（默认 `config/`） |
| `interface-fault-rca diagnose` | 跑一次完整主路径并打印候选排序 | `--window <起>/<止>`、`--input <目录或文件>`、`--top-n` |
| `interface-fault-rca clean` | 按保留期滚动清理本地分区 | `--dry-run`（只看不动）、`--retention-days` |
| `POST {OPS_TICKET_BASE_URL}/api/v1/tickets` | 确认后向运维工单系统建单 | 请求体含 `interface_code`/`service_name`/`occurred_at`/`evidence_refs[]`/`reporter`；请求头 `Authorization` + `Idempotency-Key` |
| `GET {PROM_BASE_URL}/api/v1/query_range` | 只读拉取主机与中间件指标序列 | `query`/`start`/`end`/`step` |

### 错误与降级

| 场景 | 表现 | 处理方式 |
|------|------|----------|
| 缺必填凭据 | 启动即报「缺少配置项 ESB_AUDIT_DB_HOST」并指明读哪个环境变量 | 按提示补齐后重启；**不会**退回本地样例数据 |
| 某一来源连不上 | 该来源本轮记失败、采集游标不动，另外两路照常采集 | 连续失败按退避重试；运行摘要里显示该来源的失败原因码 |
| 来源表列名或类型变了 | 报「列 duration_ms 类型不符」，该批整批不入库 | 按报错提示改 `config/pipelines.toml` 的映射表；不会写半份数据 |
| 模型端点超时或不可达 | 窗口顶部横幅「模型不可达，以下为规则基线结论」，结论标 `degraded` | 仍可人工确认建单，必要时人工补写原因字段 |
| 模型返回结构不合规 | 该候选整条丢弃，不进台账 | 运行摘要里看结构校验失败计数；程序不会「尽力修补」后放行 |
| 查询窗口过大 | 返回 Top-N 候选并明确提示「窗口过大」 | 缩小时间窗，或调高 `config/` 里的扫描与内存上限 |
| 建单被工单系统拒绝 | 台账保留在待确认状态并记失败原因码 | 修好凭据后重试；同一窗口不会产生第二条工单 |

### 对接现有系统

| 对端系统 | 协议 / 方向 | 关键字段规范 | 凭据位 |
|----------|--------------|--------------|--------|
| 院内 ESB / API 网关接口流水库 | MySQL wire 5.7/8.0 · **读**（只读账号） | `interface_code`/`service_name`/`vendor_name`/`host`/`request_time DATETIME(3)`/`response_code`/`duration_ms`/`caller_system`；列名走映射表 | `ESB_AUDIT_DB_*` |
| 主机与中间件指标 | HTTP · **读** | `GET /api/v1/query_range?query=&start=&end=&step=`；响应信封 `status`/`data.resultType=matrix`/`data.result[].values[]` | `PROM_BASE_URL`/`PROM_BEARER_TOKEN` |
| 应用与网关错误日志目录 | 文件目录 · **读**（只读） | `*.log`/`*.jsonl`；增量游标 `(path, size, mtime)`；时间戳支持秒 / 毫秒 / ISO8601 | `ESB_LOG_DIR`/`APP_LOG_DIR` |
| 院内运维工单系统 | HTTP POST · **写**（主路径终点） | 请求体 `{ticket_type,severity,summary,description,interface_code,service_name,occurred_at,evidence_refs[],reporter}` | `OPS_TICKET_BASE_URL`/`OPS_TICKET_TOKEN` |

## 典型场景

### 场景 1：夜班告警亮了，早交班前要一句结论

1. 值班工程师在主窗口里确认三路来源已连通（托盘图标为绿），把时间窗拖到昨夜 20:00 到今早 08:00。
2. 程序按劣化倍数把候选排好，展开任意一条就能看到对应的流水行、错误日志行和指标采样点。
3. 他挑中第一条，把说明文字复制进交班记录；台账里状态停在「候选已排序」，等点确认。

```bash
# 等价的一次性跑法（同样走完整主路径）
interface-fault-rca diagnose \
  --window 2026-11-09T02:00:00+08:00/2026-11-09T02:30:00+08:00 \
  --input fixtures/night/ --top-n 5
```

### 场景 2：确认后把带证据的说明提交给运维工单系统

1. 值班人在归因卡上点「确认建单」，弹窗里逐条列出将要提交的字段（接口编码、服务名、发生时间、证据引用、值班人）。
2. 他核对无误后提交；程序带上幂等键提交，工单号回写本地台账，状态推进到「已建单」。
3. 交班记录里写上工单号即可；厂商对接时按证据引用逐条回查原文。

```bash
# 幂等键由接口编码、服务名与时间窗共同算出；同一窗口重复提交只会有一个工单号
# interface-fault-rca ticket --ledger <台账行 ID> --reporter <值班人姓名>
```

### 场景 3：每周补接口登记表

1. 值班主管在主窗口里打开「接口登记缺口」，看到本周有多少行数据没能对上接口登记表。
2. 程序导出缺口清单（CSV，逐行可分派）与覆盖度报告（Markdown，含表格）。
3. 维护人照单补录；补录后字典热加载生效，历史结论仍保留它当时用的字典版本。

覆盖度 Markdown 与缺口清单 CSV（`binding-gaps.csv`）由 `binding::interface_dict::export_coverage_report()` 导出到指定目录，交给信息科按单补录；该入口以库函数形态提供，并由 `tests/dict_coverage.rs` 与 `tests/dict_reload.rs` 做真实断言（未映射值标 `unbound`、一码多服务拒绝、热加载保留历史字典版本）。

## 架构与数据流

```text
  院内 ESB 流水库(MySQL,只读)      指标端点(HTTP,只读)      错误日志目录(只读)
            │                              │                        │
            └──────────────┬───────────────┴──────────────┬─────────┘
                           ▼                              ▼
              ┌───────────────────────┐        ┌────────────────────────┐
```

### 关键不变量

- **幂等**：每行带 `__tsid`（来源 + 毫秒时间戳 + 接口编码 + 服务名 + 事件类型 的稳定哈希）；同一批数据重放两次，入库行数不变，不产生第二条。
- **证据可回查**：证据行 ID 在来源内单调分配并持久化，重启后不重号；结论里的引用必须命中本次窗口的行集合，窗口外的引用一律拒绝。
- **状态不误推进**：自动流程最多把状态推到「候选已排序」；「待确认」只能由人工动作触发，「已建单」只能由建单真实成功触发。模型不可达、校验失败、超限降级等任何异常路径都推不动这两步。
- **失败不静默改数据**：来源列名或类型不符 → 整批不入库；日志脏行 → 计数并可回查，不悄悄丢掉；模型结论引用了不存在的证据行 → 整条候选丢弃。
- **不越界**：对院内系统只读，唯一出站写是确认后的工单提交，且带幂等键；不修改任何配置，不重启服务。

## 安全与合规边界

- 程序对院内 ESB 流水库、指标端点、日志目录**只读**，不修改任何配置、路由或表结构；唯一出站写是值班人确认后的工单提交。
- 全程只处理接口、服务、主机、状态码等运维维度，**不落患者可识别明细**，也不把日志正文写进本地台账或审计记录（只留摘要与证据行 ID）。
- 模型只产出候选结论与说明文字，**不自动建单、不自动改配置、不自动重启服务**，最终判断与建单由值班人承担。
- 凭据一律从环境变量读取，日志与错误提示中出现的凭据一律以掩码形式呈现。
- 本地数据默认保留 7 天（可配），按分区滚动清理；法定日志留存义务由日志源自身承担，与本程序不冲突。

## 验收与自检

| 验收项 | 命令 | 期望结果 |
|--------|------|----------|
| 凭据位齐全 | `test -f .env.example && grep -c '^MODEL_' .env.example` | 5 个模型相关位与全部 ESB / Prom / 工单位都在清单里，无真实密钥 |
| 配置可解析 | `cargo test config_and_errors` | 缺任一必需凭据时报出对应错误码，且不退回本地替身 |
| 主路径可跑通 | `cargo run -- diagnose --window 2026-11-09T02:00:00+08:00/2026-11-09T02:30:00+08:00 --input fixtures/night/` | 终端输出至少 1 条候选，每条带证据行 ID；台账状态为「候选已排序」 |
| 判定质量可证伪 | `cargo test --test gold_regression` | 52 例金标准逐例断言通过（含 25 例负样本），语料 payload 与 `domain/cases/` 逐字一致 |
| 唯一入口说明 | `test -f docs/RUNBOOK.md` | 参数、默认值、输入样例、产物路径、字段核对表与一次真实回显齐全 |
| 重放不重复 | `cargo test idempotency_replay` | 同一批输入摄取两次，入库行数不变 |
| 证据可回查 | `cargo test rowid_stability` | 给定证据行 ID 能定位到原行且字段一致；重启后 ID 不重号 |

| 确认前零出站 | `cargo test writeback_ticket` | 未确认时出站调用计数为 0；确认后请求字段与幂等键逐项匹配 |
| 大窗口不拖死 | `cargo test query_limits` | 超上限返回 Top-N + 「窗口过大」提示，不崩溃、不静默截断 |
| 界面主题一致 | `cargo test ui_theme` | 四个语义色在深色背景上对比度达标，来源到语义色映射唯一 |
